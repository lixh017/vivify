## 三、整体战略：NemoVideo 混合模式

### 3.1 为什么选这条路

**3 个候选路径的对比**：

| 路径 | 优 | 劣 | OPC 的选择理由 |
|------|----|----|----------------|
| 🛠️ 纯做工具 | 可规模化、长期平台价值 | 启动慢、护城河靠产品力 | 太慢，缺业务验证 |
| 🎬 纯做 IP 工作室 | 低成本起、快迭代 | 5% 胜出率、不可规模化 | 太赌，不可持续 |
| 🔀 NemoVideo 混合 | 业务驱动工具、工具反哺业务 | 资源要求高 | ✅ **选这个** |

**NemoVideo 模式的核心逻辑**（[腾讯新闻报道](https://so.html5.qq.com/page/real/search_news?docid=70000021_266691fbbb975152)）：
- 创始团队从 TikTok 离职创业
- 定位"爆款仿剪 Agent 工具"
- **长期愿景：视频领域的 Canva——创作者在社区沉淀和交易自己的视频制作 agent**
- 拿了 IDG + 锦秋**近千万美元**融资
- 关键路径：**先跑自己的 IP → 沉淀 workflow → 工具化 → 平台化**

## 四、Phase 1 详细方案：熊猫 IP

### 4.1 IP 形象定义

#### 4.1.1 视觉形象
- **物种**：熊猫（Q 萌 + 国潮风）
- **基础设定**：成年熊猫，会站立、双手会做手势
- **穿着**：可选 3-5 套标志性服饰
  - 标配：折扇 + 茶盏 + 山水背景
  - 春款：樱花和服
  - 夏款：竹杖草帽
  - 秋款：红叶披风
  - 冬款：毛绒斗篷 + 围炉煮茶
- **AI 形象一致性**：用即梦/可灵的"角色锚定"功能（同一 IP 多次生成保持形象一致）
- **关键禁忌**：不能太可爱/太萌、不能太"网红脸"、必须保留哲学气质

#### 4.1.2 声音设定
- **音色**：低沉稳重、治愈系男声（30-40 岁感）
- **方言**：普通话为主，可选川话（熊猫故乡）
- **AI 配音**：可用 ElevenLabs / 字节火山 / 剪映 AI 配音
- **节奏**：语速偏慢、留白多、像在跟你聊天

#### 4.1.3 人设核心
- **性格关键词**：治愈 / 御宅 / 哲学 / 国潮 / 不急不慢
- **口头禅**："慢慢来" / "你说呢" / "嗯，这个有意思"
- **世界观**：住在山中竹林，有自己的小院。会读诗、会喝茶、会发呆
- **行为模式**：
  - 不追热点、不迎合流量
  - 不卖惨、不说教
  - 偶尔"毒舌"但有温度
  - 经常"反鸡汤"
  - 喜欢自言自语式表达

#### 4.1.4 不做的事（边界）
- ❌ 不做新闻/资讯解读
- ❌ 不做带货（至少前 3 个月）
- ❌ 不做真人出镜对比
- ❌ 不做"熊猫 + 美女"擦边
- ❌ 不做"虚拟偶像演唱会"等高成本

### 4.2 平台矩阵与内容策略

#### 4.2.1 平台优先级

| 平台 | 角色 | 内容形态 | 频率 | 原因 |
|------|------|----------|------|------|
| 🥇 **抖音** | 主流量场 | 1-3 分钟治愈口播 + 偶尔短剧 | 3-5 条/周 | 流量最大、短剧分账机会多 |
| 🥇 **B 站** | 主品牌场 | 5-10 分钟国风/哲学中视频 | 1-2 条/周 | 御宅/哲学调性最贴、周边/联名优 |
| 🥈 **小红书** | 品牌联名场 | 9 图图集 + 30 秒短口播 | 5-10 条/周 | 女性 25-40 主流、治愈调性贴 |
| **海外 TikTok** | 远期 | 熊猫全球认知强 | 3-6 月后开 | 熊猫的天然优势 |

#### 4.2.2 内容选题方向（治愈/哲学/国潮 各占 1/3）

**治愈类（33%）**
- 每日金句（"今天熊猫想跟你说..."）
- 情绪疏导（"如果你今天很累..."）
- "如果熊猫陪你度过一天"Vlog
- "熊猫的疗愈清单"（音乐/茶/书/电影推荐）

**哲学类（33%）**
- 人生感悟（"时间不会说慌"）
- 对现代焦虑的反思（"为什么我们越来越忙"）
- 存在主义轻讨论（"我为什么要努力"）
- 反鸡汤（"成功学的 3 个谎言"）

**国潮类（33%）**
- 历史小故事（用熊猫视角讲）
- 古诗新解（"李白写这首诗时在想什么"）
- 传统美学（茶道/香道/古琴）
- 节日专题（春节/中秋/端午的熊猫故事）

#### 4.2.3 平台内容差异化

| 平台 | 平台特性 | 我们的适配 |
|------|----------|------------|
| **抖音** | 黄金 3 秒钩子、完播率、互动 | 开头 5 秒必须出金句/反常识结论、节奏要快、结尾留互动 |
| **B 站** | 中视频耐看、弹幕文化、二次元 | 中视频 5-10 分钟、可深度展开、玩弹幕梗（"下次讲讲..."） |
| **小红书** | 图文+种草、女性审美 | 9 图视觉要精致、标题党但不 low、收emoji、tag 要多 |

#### 4.2.4 内容复用关系

```
1 个核心选题（如"为什么我们越来越忙"）
            ↓
  ┌─────────┼─────────┐
  ↓         ↓         ↓
抖音 1-3分钟   B 站 5-10分钟   小红书 9图
  ↓         ↓         ↓
 同核心，   深度展开，  视觉化重做，
 节奏快     讲透       标题党
```

**关键约束**：每个平台的内容**不是简单剪辑**，而是要按平台调性重做。

### 4.9 web UI MVP 5 页面设计

> 这是 Phase 1 的"隐藏任务"——**为 Phase 2 平台化准备**。M2 集中搭出来，M3-M6 边用边迭代。

#### 4.9.1 5 个核心页面（更新：增加"知识库"）

**页面 1：选题看板**（kanban 风格）
- 4 列状态：`想法` → `评估` → `待写` → `已发布`
- 卡片字段：标题、平台标签（抖音/B站/小红书）、选题角度、预期表现、所属系列、关联脚本链接
- 操作：拖拽改状态、点开看详情、批量打标签
- Agent 集成：「AI 选题」按钮 → 调 Claude API 生成 5 个候选选题

**页面 2：脚本库**（搜索 + 标签）
- 列表视图：标题、平台、风格、字数、关联选题、最后编辑时间
- 详情视图：富文本编辑 + 元数据（钩子/转折/结尾 标注）
- 搜索：全文搜索 + 按平台/风格/标签筛选
- 关键能力：**风格库**——把每篇脚本的"风格指纹"存下来（钩子类型、句式偏好、节奏等）
- Agent 集成：「AI 改写」「AI 拟人化」按钮 → 调 Claude API

**页面 3：内容日历**（甘特/日历视图）
- 月/周视图切换
- 字段：日期、平台、标题、状态、对应脚本链接、发布链接
- 操作：拖拽改时间、批量发布排期
- 关键能力：**跨平台协调**——同一选题可以一键复制为多平台版本

**页面 4：表现 dashboard**（含"复盘"能力）
- **数据存储 + 手动录入**：每条发布内容绑定一个 ContentItem，团队手动录入播放/互动/涨粉数据（M1-M3）
- **半自动抓取**（M4+）：评估接入蝉妈妈/飞瓜 API 或自建简单抓取脚本
- **核心指标**：单条播放/互动/涨粉、累计趋势、爆款标记
- **关键能力：爆款复盘工作流**——一键触发"为什么这条爆了"分析（用 Claude API）
  - 输入：视频链接 + 表现数据 + 脚本 + 选题上下文
  - 输出：AI 复盘报告（结构化：成功要素/可复用模式/数据洞察/改进建议）
- **关键能力：选题趋势感知**（针对熊猫 IP 垂类）
  - 不做通用榜单（那是蝉妈妈的事）
  - 做"我们垂类的趋势"——基于我们已发布内容的横向对比
- **Phase 2 路线**：
  - M7+ 可选接入蝉妈妈/飞瓜 API（成为数据源）
  - M9+ 可选自建简单抓取（轻量级）

**页面 5：知识库**（SOP/笔记/复盘沉淀）—— **核心页面，不依赖 Notion/飞书**
- **树状层级结构**：IP → 一级目录（如"风格指南/选题 SOP/复盘档案/Prompt 库/决策日志"）→ 文档
- **Markdown 富文本编辑**：支持代码块、表格、图片、链接
- **全文搜索**（SQLite FTS5）：跨所有知识库文档
- **标签系统**：多 tag 分类、tag 间互引
- **交叉引用**：知识库文档可链接到具体 Topic/Script/ContentItem（如"这个 hook 来自 #S005 选题"）
- **核心内容类型**：
  1. **IP 风格指南**——熊猫的视觉/声音/人设详细设定
  2. **选题 SOP**——"如何评估一个选题"、"如何找钩子"
  3. **脚本 SOP**——"口播稿的 7 段结构"、"钩子公式"
  4. **Prompt 库**——可灵/即梦/Claude 用的 prompt 模板，按场景分类
  5. **复盘档案**——每月复盘、爆款复盘、失败复盘
  6. **决策日志**——为什么选 A 不选 B（架构/工具/合作方）
  7. **平台规则笔记**——抖音/B站/小红书最新规则、限流规避
- **Agent 集成**：
  - 「AI 总结」按钮：对当前文档生成摘要
  - 「AI 关联」按钮：根据当前文档自动推荐相关的 Topic/Script/ContentItem
- **协作**：极简——单人编辑，文档用 Git 版本管理（M5+ 再说）
- **为什么必须自建**：
  - SOP 与工作流深度耦合，不能脱离上下文
  - 知识库文档需要交叉引用 Topic/Script/ContentItem，Notion 做不到
  - 风格库是 OPC 差异化资产，不该放在第三方

#### 4.9.2 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| **前端** | Next.js 14 (App Router) + TypeScript | 已有 frontend-design 插件、SSR/SSG 友好 |
| **UI 库** | shadcn/ui + Tailwind CSS | 现代风格、可定制、不锁定 |
| **后端** | **Go 1.22+ + Gin + GORM** | 单二进制部署、并发强、AI 集成成熟、性能好 |
| **DB** | SQLite (MVP) → PostgreSQL (Phase 2) | 0 运维起步、GORM ORM、迁移工具 gormigrate |
| **LLM 集成** | `github.com/anthropics/anthropic-sdk-go` | 官方 Go SDK、Claude API 主力 |
| **视频数据抓取** | M3 前手动；M4+ 评估 yt-dlp（go binding）/ 官方 API | 避免早期过度工程 |
| **MCP server** | `github.com/modelcontextprotocol/go-sdk` | 官方 Go MCP SDK、agent-agnostic 暴露 |
| **依赖管理** | Go modules | 标准工具链 |
| **部署** | 单台 VPS（Hetzner/腾讯云轻量） | Go 单二进制 ~20MB Docker 镜像、启动快 |
| **监控** | 极简：日志 + UptimeRobot | 不上 Sentry/Datadog 等 |

**为什么选 Go**（用户决策）：
- ✅ **单二进制部署**——不用管 Python venv、依赖冲突
- ✅ **MCP SDK 官方支持好**——`go-sdk` 比 Python SDK 更稳定
- ✅ **AI 库成熟**——`anthropic-sdk-go` 官方维护、并发好
- ✅ **性能强**——API 响应快、内存占用低
- ✅ **强类型**——编译期抓错、IDE 友好
- ⚠️ AI/ML 库比 Python 少——但 OPC 主要是调 API，**影响不大**
- ⚠️ 团队 Go 经验需要——这是最大风险（见 4.7 风险）

#### 4.9.4 MCP Server（agent-agnostic 出口）

**为什么 M2 就要做**：MCP 是 Phase 1 给 Phase 2 留的关键接口——确保 OPC 自研 agent 跑出来的工作流，**自然能被外部 agent（Claude Code CLI 等）复用**。

**实现**：`github.com/modelcontextprotocol/go-sdk`（官方 Go MCP SDK）

**M2 暴露的最小工具集**：
```go
// 用 go-sdk 注册 10 个工具
mcp__opc__list_topics(platform, status) → []Topic
mcp__opc__create_topic(title, angle, platform) → Topic
mcp__opc__get_script(script_id) → Script
mcp__opc__create_script(topic_id, content) → Script
mcp__opc__update_script(script_id, content) → Script
mcp__opc__log_content(script_id, platform, url) → ContentItem
mcp__opc__get_performance(content_id) → Metrics
mcp__opc__generate_topics(seed, platform) → []Topic  // 内部调 anthropic-sdk-go
mcp__opc__humanize_script(script_id) → Script         // 反 AI 检测
mcp__opc__deconstruct_viral(url) → Analysis           // 拆爆款
```

**效果**：OPC 团队既能在 web UI 里用，又能在 Claude Code CLI 里通过 MCP 调这些能力。

**为什么用 Go SDK**：
- 与 Gin 后端共享类型定义（`type Topic struct` 直接复用）
- 单二进制部署 MCP server，与 API server 一起打包
- 性能更好、内存更低
- 官方 SDK 维护及时

### 4.10 自建 vs 外包 决策框架

> 这是 OPC 平台的关键设计原则——确保我们做对的事、不自欺欺人。

#### 4.10.1 三条判断标准

| 标准 | 含义 |
|------|------|
| **是否定义 OPC 的差异化** | 自建 = 这事换别人做不出来 |
| **是否日常依赖、与工作流深度耦合** | 自建 = 团队每天用、影响产出 |
| **是否能在 6 个月 / 1 个开发者 / ¥10 万内完成** | 自建 = 范围可控 |

**三条同时满足** → 自建
**任一不满足** → 外包（用第三方）或合作（API 集成）

#### 4.10.2 已做的决策

| 能力 | 决策 | 理由 |
|------|------|------|
| **LLM 调用** | **自建 agent**（基于 Claude API） | OPC 差异化、人格化输出 |
| **视频生成** | **外包**（可灵/即梦/剪映） | 模型巨头护城河 |
| **图像生成** | **外包**（即梦/MidJourney） | 同上 |
| **音乐生成** | **外包**（Suno） | 同上 |
| **跨平台数据抓取** | **外包**（蝉妈妈/飞瓜） | 10+ 年数据护城河 |
| **我们自己的表现数据** | **自建** | 工作流依赖、差异化 |
| **复盘分析** | **自建 agent** | 差异化能力 |
| **选题趋势感知**（针对我们 IP） | **自建** | 垂类精准 |
| **笔记/SOP/知识库** | **自建**（页面 5） | 与工作流深度耦合、交叉引用需求 |
| **选题库** | **自建**（页面 1） | 工作流核心 |
| **脚本库** | **自建**（页面 2） | 风格库是核心资产 |
| **内容日历** | **自建**（页面 3） | 工作流核心 |

#### 4.10.3 复审原则

任何新功能提议，先过 4.10.1 三条标准。**避免"我们也能做"的诱惑**——尤其在以下场景：
- 看到竞品有 X 功能 → 不等于我们要做
- "反正团队有 Go 经验" → 不等于要自建
- "Notion 用着还行" → 不代表它是终局

### 5.3 Phase 1→2 的 Go/No-Go 决策点

**Go 条件（满足任一即 Go）**：
- 6 个月内 1 平台 10 万+粉
- 1 条 500 万+播放爆款
- 主动品牌询问 ≥3 个
- 完整可复用 SOP

**No-Go 条件**：
- 6 个月总粉丝 <5 万
- 无百万级爆款
- 完整 SOP 没沉淀下来

**Pivot 条件（不 No-Go 但换方向）**：
- 有爆款但难复制 → 换赛道/换 IP
- 有粉丝但变现困难 → 换变现路径
- SOP 沉淀不下来 → 团队配置问题
